Smart Redirect Guard — mock test site

A local, self-contained page for exercising all three protection layers. No real advertising network is ever contacted.

Serve this over HTTP, not file://. From the project root run python -m http.server 8080 --directory tests/mock-site, then open http://localhost:8080/. The server answers on both localhost and 127.0.0.1, and Chrome treats those as two different sites — which is what makes the cross-site tests real.

For the tab-closing tests, first import srg-test-config.json (Dashboard → Settings → Import). It registers 127.0.0.1 as an example ad domain so a tab opened there is a confirmed high-confidence advertisement. Without it the extension correctly refuses to close an unknown host — which is itself test 6.

Layer 1 — new-tab protection

Test 2 — known advertising tab

Opens a new tab on the other origin, on a path matching the */popunder* rule.

Expected: the new tab is classified high confidence and closes after the configured delay. This page stays open and becomes active again. "Tabs closed" increases.

Test 3 — legitimate external link

A normal target="_blank" link to an ordinary page on the other origin.

Open legitimate external link

Expected: the tab stays open. Cross-origin alone is not evidence of an advertisement.

Test 6 — unknown domain

Opens a tab on a host the extension has never seen and has no rule for.

Expected: not closed. An unfamiliar domain is not treated as malicious. At most a low or medium activity row appears.

Layer 2 — same-tab redirect protection

Test 5 — suspicious same-tab redirect

Replaces this page with a URL matching the */ad-redirect* blocking rule.

Expected (one of two, both correct): the static rule blocks the request before it leaves Chrome (ERR_BLOCKED_BY_CLIENT) and the event is logged as blocked; or, if no rule covered it, the navigation completes and the popup offers Go back. The extension never navigates back by itself.

Test 4 — login redirect

Redirects this tab to a path containing /login on the other origin.

Expected: untouched. Authentication paths are a hard veto that outranks every positive signal, so sign-in flows never break.

Test 14 — trusted site

Add localhost as a trusted site (popup → Trust this site, "new tabs" scope), then run test 2 again.

Expected: the tab now stays open, and the activity row shows the trusted exemption. Remember to remove the trust afterwards.
